# PostgreSQL 16 disposable deployment verification — 14 August 2026

## Result

**PASS**, subject to the explicit limitations below. The checked-in Prisma migrations and application PostgreSQL adapter were exercised against a disposable PostgreSQL **16.15** cluster. ## Findings discovered and corrected

### F1 — runtime certificate trust mismatch

The first Node/Prisma runtime attempt failed closed with `P1011: self-signed certificate`. PostgreSQL CLI migration commands using `sslmode=require` had not exposed the same trust behavior. The cluster certificate was replaced with a disposable CA-signed leaf containing `DNS:localhost` and `IP:127.0.0.1`; application and final migration checks then used `sslmode=verify-full` with the CA root. TLS 1.3 verification passed.

**Consequence:** production must use a certificate chain trusted by the runtime and explicit server-identity verification. Encrypted transport alone is insufficient.

### F2 — nullable SQL/domain boundary mismatch

Live transaction and outbox reads initially failed Zod parsing because Prisma returns nullable SQL columns as `null`, while canonical optional domain fields are omitted/`undefined`.

`lib/infrastructure/prisma-adapters.ts` now omits top-level SQL-null columns before canonical parsing while retaining nested JSON `null`. All live integration and HTTP tests passed after the fix.

## Limitations

- Trusted production authentication is not implemented; demo request headers were used only under explicit demo mode.
- NATS and the outbox dispatcher are not implemented, so no external delivery was tested or claimed.
- Browser interaction/accessibility remains unverified because no supported browser executable is available.
- This was an isolated disposable cluster, not a managed-provider failover, restore-time, or load test.
- The one-shot operational snapshot does not replace continuous observability.

## Teardown evidence

The production verification app was stopped first. PostgreSQL then accepted a smart shutdown and logged `database system is shut down`. The disposable directory `/tmp/ase-pg16-verify`—including the database, socket, logs, backup, WAL archive, certificates, and mode-`0600` credentials—was deleted.

The unused package-created `16/main` cluster was dropped. PostgreSQL 16 server/client packages, PGDG common packages and their run-specific automatic dependencies were purged; the `trixie-pgdg` Apt source and packaged PGDG key directory were removed.

Independent final probes passed:

- `pgrep -x postgres` found no PostgreSQL process;
- `ss -ltn` found no TCP listener on port `55432`;
- `/tmp/ase-pg16-verify`, `/var/lib/postgresql/16/main`, and `/etc/postgresql/16/main` were absent;
- `/etc/apt/sources.list.d/pgdg.sources` and `/usr/share/postgresql-common/pgdg` were absent; and
- `postgresql-16`, `postgresql-client-16`, `postgresql-common`, and `postgresql-client-common` were not installed.

Teardown therefore completed without retaining the disposable database or its secrets. This checked-in sanitized report is the retained evidence record.
